# dub (b1) 병합에서 나온 후보 2건 — 2026-10-18

출처: dub 저장소, 구현 계획 (b1) 골든셋 도구 + 평가 하네스. 둘 다 실제로 밟은 것이다.

## 1. 검증 명령의 출력을 파이프로 거르면 실패가 가려진다 (coding-conventions 검증 게이트)

**관찰:** `./scripts/check 2>&1 | grep -E "✗|✓" && git commit …`으로 돌렸다. 검사는 ruff 오류로 실패했고 `✗ 실패` 줄도 출력됐다. 그런데 파이프의 종료 코드는 마지막 명령(grep — 줄을 찾았으니 0)의 것이라 커밋이 그대로 됐다. push 전에 알아채고 고쳐 다시 커밋했다.

**후보 규칙:** 완료를 판단하는 검증 명령은 파이프 끝에 두지 않는다. 출력은 파일로 받고 종료 코드로 판단한 뒤 필요한 줄만 본다(`./scripts/check > log 2>&1 && grep … log && git commit …`). 또는 `set -o pipefail`. 「실행 없이 완료 주장 금지」의 실행 절차로 붙일 만하다 — 실행은 했지만 결과를 잘못 읽은 경우다.

## 2. Python `round()`는 짝수 쪽으로 반올림한다 — 시간 → 프레임·샘플 변환에 쓰지 않는다 (python 스택)

**관찰:** ms를 10ms 프레임 경계로 바꿀 때 `round(ms / 10)`을 썼더니 45ms → 4, 55ms → 6이 돼서 같은 길이 구간의 프레임 수가 달라졌다. 같은 저장소의 (a2) vad 단계에서도 샘플 → ms 변환을 half-up으로 따로 맞춘 적이 있어 두 번째다.

**후보 규칙:** 시각·샘플·프레임 경계 변환은 정수 half-up(`(x + d // 2) // d`)으로 쓰고, 경계값(정확히 절반) 테스트를 하나 둔다.
