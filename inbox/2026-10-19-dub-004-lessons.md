## 2. `gh auth refresh -s project`는 대화창 `!`로는 안 되고, Enter를 눌러야 승인 결과를 받아 간다 (todo-workflow — Project 권한)

**관찰:** (1) 대화창 `!`로 실행하면 비대화형이라 `--hostname required when not running interactively`로 끝난다. (2) 일반 터미널에서 `-h github.com`을 붙여 실행하고, 브라우저를 따로 열어 코드를 넣고 승인했는데도 토큰 권한이 그대로였다 — 터미널이 `Press Enter to open ...`에서 멈춰 있어 gh가 승인 결과를 받으러 가지 않았다. Enter를 누르자 바로 반영됐다. 사용자는 그동안 「gh로는 Projects를 다룰 수 없다」고 알고 있었다(설정 화면의 세분화 토큰(fine-grained PAT)에서는 개인 계정 Projects 권한을 고를 수 없어서다 — gh는 OAuth 토큰 `gho_`라 무관하다).

**후보 규칙:** todo-workflow의 `gh auth refresh -s project` 안내를 「사람이 일반 터미널에서 `gh auth refresh -h github.com -s project` → **Enter** → 브라우저에서 코드 입력·승인 → `✓ Authentication complete.` 확인」으로 바꾼다. 확인은 `gh api -i user`의 `X-Oauth-Scopes`. 「라벨을 바꿔도 보드 칸은 움직이지 않는다」는 이미 스킬에 있다 — 실제로도 라벨만 `status:진행`인 항목들이 보드 Todo에 머물러 있었다.

## 3. torch `named_buffers()`는 공유 텐서를 한 번만 돌려준다 — dtype을 일괄로 바꿀 때 일부가 빠진다 (python/torch 스택)

**관찰:** 가져온 모델(Bandit v2)을 Apple MPS(float64 미지원)에 올리려고 적재 뒤 `for name, buf in model.named_buffers(): ... buf.float()`로 바꿨다. 같은 텐서를 여러 모듈이 버퍼로 공유하고 있어 `named_buffers()`(기본 `remove_duplicate=True`)가 첫 모듈 것만 돌려줬고, 나머지 모듈에는 float64가 남아 `model.to("mps")`가 그대로 실패했다. 모듈마다 `_buffers`를 돌며 바꾸자 192개가 다 바뀌었다. 최종적으로는 원천(텐서를 만드는 곳)에서 float32로 고쳤다.

**후보 규칙:** dtype·장치를 일괄로 바꾸는 코드는 `named_buffers(remove_duplicate=False)`나 `for m in model.modules(): m._buffers`로 돈다. 더 나은 길은 원천에서 dtype을 정하는 것이다. 바꾼 뒤에는 「모델 텐서의 dtype 집합」을 확인하는 테스트를 하나 둔다(가중치 없이 모델만 만들어 검사할 수 있다).
