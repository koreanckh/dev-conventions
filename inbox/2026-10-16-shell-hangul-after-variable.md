# 후보: 셸 스크립트에서 변수 바로 뒤에 한글을 붙이지 않는다

- **출처:** dub `scripts/check` 시제품(2026-10-16) — 구현 계획 (a1) Global Constraints에 반영됨
- **환경:** macOS 기본 `/bin/bash` 3.2.57, `LANG=en_US.UTF-8`, `set -euo pipefail`

## 관찰된 실패

```bash
fail "$d/pyproject.toml의 dev 그룹에 $pin이 없다"
```

bash가 `$pin` 뒤의 한글 첫 바이트까지 변수 이름으로 읽어 `pin�: unbound variable`로 죽었다. 의도한 `✗` 안내 메시지는 나오지 않고 스크립트만 멈췄다. 정상 경로에서는 이 줄이 실행되지 않아, **검사를 일부러 깨뜨려 보기 전까지 몰랐다** — 실패를 알려야 할 코드가 실패할 때만 깨진다.

같은 스크립트의 `"$tool이 없습니다"`도 같은 문제였다. `'$line'이`, `$d/…`처럼 변수 뒤에 ASCII 구분자가 오면 문제없다.

## 승격안 (coding-conventions 공통 규칙 후보)

1. 셸 문자열에서 변수 바로 뒤에 ASCII 구분자가 아닌 글자(한글 등)가 오면 `${var}`로 감싼다. 헷갈리면 항상 `${var}`.
2. 실패 메시지 경로(검사 스크립트의 `fail …`)는 일부러 실패시켜 한 번씩 돌려 본다. 정상 경로만 돌리면 이런 버그가 남는다.

lint로 잡으려면 shellcheck가 후보지만, 이 경우를 경고하는지는 확인하지 않았다.
