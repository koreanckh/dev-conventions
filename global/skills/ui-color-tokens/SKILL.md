# UI 색 토큰

화면 색을 **역할 토큰 짝**으로 쓰고 그 짝을 **테스트로 지키는** 규칙. 다크 모드를 지금 붙이지 않아도 처음부터 적용한다 — 팔레트 이름이 쌓인 뒤 다크 모드를 붙이면 결함이 한 커밋에 한꺼번에 생긴다(아래 "주의"). 어떤 색을 쓸지(시각 방향)는 이 문서가 아니라 `design` 파라미터의 결정이 정한다 → [에이전트 작업 규칙](../agent-workflow/SKILL.md)의 "화면이 있는 작업은 디자인을 먼저 정한다". 예시는 Tailwind CSS 3 + shadcn/ui(`cva`·`cn`) 기준이다.

## 원칙

- **색은 역할 토큰으로만 쓴다.** CSS 변수로 역할(페이지 바탕·카드 바탕·글자·강조·강조 위 글자 …)을 정의하고, Tailwind엔 역할 이름만 노출한다. **바탕 역할마다 그 위 글자 역할을 짝으로 둔다**(Material 3의 `X` / `on-X`). 컴포넌트에서 팔레트 이름(`slate-900`, `white`)을 쓰지 않는다.
- **고정 색도 이름을 붙인다.** 늘 어두운 영상 바탕처럼 테마를 타지 않아야 맞는 자리는 팔레트 이름 대신 이름 붙은 고정 색(예: `dark-surface`)을 쓴다. 그러면 아래 금지 검사에 예외가 필요 없다.
- **묶음은 짝을 통째로 담는다.** `@apply` 클래스와 `cva` 변형은 바탕·글자·호버를 함께 정한다. 바탕만 두고 글자를 상속에 맡기려면 그 바탕이 역할 색이어야 한다.
- **상태는 새 색 짝을 만들지 않는다.** 같은 짝에 투명도로(`disabled:opacity-40`). 다크 비활성을 막으려 따로 만든 짝(`disabled:text-white`)은 라이트에서 1.44:1이 됐다.
- **색은 변형으로만 고른다.** 호출부에서 `className="bg-white"`로 덮어쓰지 않는다 — `cn`(tailwind-merge)은 바탕만 바꾸고 짝 글자(`text-accent-fg`)는 남겨 흰 바탕에 흰 글자가 된다.
- **빈 자리를 남기지 않는다.** `color-scheme`을 테마 규칙마다 선언한다(안 하면 폼 칸이 브라우저 기본색으로 남는다). 크기만 주는 유틸리티에는 색을 같이 준다(`ring-offset-2 ring-offset-bg` — 색이 없으면 Tailwind 기본값 `#fff`).

## 셋업 / 값 — 짝을 지키는 테스트 셋

규칙만으로는 지켜지지 않았다(아래 실패표). 셋을 함께 둔다. 기준값(대비·금지 정규식)은 테스트 코드가 정본이다.

| 테스트 | 실패 조건 |
|---|---|
| 짝 대비 | 토큰 파일을 읽어 짝마다 라이트·다크 대비를 계산해, 글자가 4.5:1 미만이다 |
| 섞임 검사 | 한 요소의 색 클래스(bg·text·border·ring·ring-offset·outline …)에 테마를 타는 색과 고정 색이 같이 있다. 「테마를 타는가」는 색 이름 목록이 아니라 설정이 CSS 변수를 가리키는지와 그 변수의 라이트·다크 값 비교로 판정한다. 전역 CSS의 `@apply`도 읽는다 |
| 팔레트 이름 금지 | 컴포넌트에 팔레트 이름이 있다. 정규식에 끝 단계(`50`·`950`)와 `white`·`black`까지 넣는다 — 50~900만 잡으면 `slate-950`·`bg-black`이 샌다(nskg `fe32322`에서 넓혔다) |

참고 구현(nskg, Next.js 15.5 · Tailwind 3.4 · shadcn/ui): 토큰 `lib/design/tokens.ts`·`app/globals.css` 상단 변수 블록, 대비 `lib/design/__tests__/contrast.test.ts`, 섞임·링 여백 `app/__tests__/theme-bridge.test.ts`, 팔레트 금지 `app/__tests__/token-adoption.test.ts`, 짝을 묶은 버튼 `components/ui/button.tsx`.

## 주의 / 알려진 불일치

**이미 팔레트 이름이 쌓인 저장소 — 「이주 다리」의 함정.** nskg는 규칙 없이 `bg-white`·`text-slate-900` 류 클래스가 약 1,300개 쌓였다(`dark:` 0개). 다크 모드를 붙이며 43개 파일을 한 번에 못 옮겨, Tailwind 설정에서 `slate`·`indigo`의 일부 단계를 CSS 변수에 잇는 다리를 놓았다. 그 커밋 하나에서 아래가 한꺼번에 생겼고, 리뷰가 한 종류씩 찾아 여섯 번에 걸쳐 고쳤다(nskg #039, 2026-09-04~07, 대비는 다크 값).

| 깨진 모양 | 예 | 대비 |
|---|---|---|
| 바탕은 테마를 타고 글자는 고정 | `bg-indigo-600 text-white` 버튼 | 1.69:1 |
| 바탕은 테마를 타고 글자는 다리에 빠진 단계(`indigo-900`) | 옅은 강조 안내 상자 | 1.37:1 |
| 바탕은 고정(`bg-white/80`), 글자는 테마를 탐 | 헤더 | 1.28:1 |
| `@apply` 묶음이 바탕(`bg-white`)만 정하고 글자는 호출부에 맡김 | 전역 `.card` | 1.20:1 |
| 배경 클래스 없는 폼 칸 + `color-scheme` 미선언 | 선택칸·입력칸 | 1.20:1 |
| `ring-offset-2`만 주고 색 없음 → Tailwind 기본 `#fff` | 포커스 링 흰 테 | — |
| 빠진 단계(`slate-950`)를 글자 역할에 잇자, 같은 이름을 바탕으로 쓰던 자리가 뒤집힘 | 코드 출력창 | 1.27:1 |

다리를 놓아야 한다면 위 테스트 셋을 먼저 둔다 — 결함 종류마다 리뷰가 따로 찾게 두지 않는다.

- Tailwind 4(CSS 우선 `@theme` 설정)에서는 확인하지 않았다. 원칙(역할 짝·묶음·테스트 셋)은 같고, 「설정이 CSS 변수를 가리키는가」를 읽는 방법만 달라진다.

## 필요한 프로젝트 파라미터

- `design` — 시각 방향 결정 문서. 이 문서는 정해진 색을 코드에 어떻게 두는지만 다룬다.
- `stack` — 예시는 Tailwind 3 + shadcn/ui 기준이다. 다른 스택이면 역할 짝·묶음·테스트 셋의 원칙만 가져간다.
